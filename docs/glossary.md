# VECAI Glossary

## Purpose

This glossary defines the key terms, abbreviations, and concepts used throughout the VECAI project.

It serves as a common reference for developers, designers, project managers, construction professionals, and stakeholders.

---

# A

## API

**Application Programming Interface.**

A set of rules that allows different software systems to communicate with each other.

---

## Architecture

The overall structure and organization of the VECAI system, including its components and how they interact.

---

## Authentication

The process of verifying a user's identity before granting access to the system.

---

## Authorization

The process of determining what an authenticated user is allowed to do.

---

# B

## Backend

The server-side part of VECAI responsible for processing requests, applying business logic, and managing data.

---

## BOQ

**Bill of Quantities.**

A detailed document listing construction materials, labour, and associated costs required to complete a project.

---

## Business Logic

The rules that determine how VECAI operates, such as calculating material usage or validating project data.

---

# C

## Client

The person or organization commissioning a construction project.

---

## Contractor

The individual or company responsible for executing construction work.

---

## CRUD

An acronym for:

* Create
* Read
* Update
* Delete

These are the four basic operations performed on data.

---

# D

## Dashboard

A summary screen displaying project information, progress, and key metrics.

---

## Database

A structured system for storing and managing application data.

VECAI uses PostgreSQL.

---

## Daily Report

A record submitted each day describing work completed, workforce attendance, site conditions, and project progress.

---

# E

## Entity

A real-world object represented in the database.

Examples include:

* User
* Project
* Supplier
* Material

---

# F

## Frontend

The part of VECAI that users interact with through their web browser or future mobile application.

---

# G

## Go

The programming language used to build the VECAI backend.

---

## Git

A version control system used to track changes in the source code.

---

## GitHub

An online platform used to host the VECAI source code and documentation.

---

# H

## HTTP

HyperText Transfer Protocol.

The communication protocol used between the client and the server.

---

# I

## Inventory

The collection of construction materials currently available for a project.

---

# J

## JSON

JavaScript Object Notation.

The data format used by the VECAI API.

---

# M

## Material Allocation

The process of assigning construction materials to specific tasks or phases of a project.

---

## Material Wastage

Construction materials that are lost, damaged, or used inefficiently during a project.

Reducing wastage is one of VECAI's primary goals.

---

## Migration

A version-controlled script used to create or modify the database schema.

---

## Module

A self-contained part of the application responsible for a specific business function.

Examples:

* Authentication
* Projects
* Documents

---

## MVP

**Minimum Viable Product.**

The smallest version of VECAI that delivers value to users while allowing early feedback.

---

# P

## PostgreSQL

The relational database management system used by VECAI.

---

## Project

A construction job managed within VECAI.

A project contains team members, documents, materials, reports, and other related information.

---

## Project Owner

The individual or organization funding or owning a construction project.

---

# Q

## Quantity Surveyor

A construction professional responsible for estimating project costs, preparing BOQs, and managing financial aspects of a project.

---

## Quotation

A supplier's pricing proposal for providing materials or services.

---

# R

## Repository

A software component responsible for reading and writing data to the database.

---

## REST API

An API architecture based on resources, HTTP methods, and stateless communication.

VECAI's backend follows REST principles.

---

## Role-Based Access Control (RBAC)

A security model that grants permissions based on a user's assigned role.

For example:

* Administrator
* Contractor
* Client

---

# S

## Site Engineer

The engineer responsible for supervising construction activities on-site.

---

## Sprint

A short development cycle focused on delivering a specific set of features.

---

## Stakeholder

Any individual or organization with an interest in a construction project.

Examples include:

* Clients
* Contractors
* Suppliers
* Architects
* Engineers

---

## Supplier

A company or individual providing construction materials or services.

---

# T

## Team Member

Any user assigned to a project.

Examples include:

* Contractor
* Engineer
* Architect
* Quantity Surveyor

---

# U

## User

Any individual with an account in VECAI.

Each user is assigned one or more roles.

---

## UUID

Universally Unique Identifier.

A unique value used as the primary key for records in the database.

---

# V

## VECAI

**Victoria Eagles Construct AI.**

A construction project management platform that helps construction teams manage projects, materials, documents, and collaboration while using AI to improve decision-making.

---

# W

## Work Output

The measurable amount of work completed during a specific period.

VECAI records work output through daily reports and project progress tracking.

# VECAI Terminology

The following terms have specific meanings within VECAI:

| Term              | Definition                                                                                      |
| ----------------- | ----------------------------------------------------------------------------------------------- |
| Project           | A construction project managed within VECAI.                                                    |
| Project Member    | A user assigned to a project.                                                                   |
| Daily Report      | A daily record of work completed on-site.                                                       |
| Material Record   | A log of materials delivered or used.                                                           |
| BOQ Item          | An individual line item within a Bill of Quantities.                                            |
| Document          | Any file associated with a project, such as contracts, drawings, permits, or reports.           |
| Dashboard         | A summary view of project status and key metrics.                                               |
| AI Recommendation | A future feature that provides data-driven suggestions based on historical project information. |

---

# Maintaining the Glossary

As VECAI evolves, new terms should be added to this glossary whenever:

* A new business concept is introduced.
* A new module is created.
* A new abbreviation is adopted.
* A construction term appears in the documentation.
* An AI-specific concept becomes part of the platform.

Maintaining a shared vocabulary helps ensure clear communication, reduces ambiguity, and improves collaboration across both the software development and construction domains.
